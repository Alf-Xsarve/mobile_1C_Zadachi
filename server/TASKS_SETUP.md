# Обновление API для Android 2.2.0

Эта сборка подключает Android 2.2.0 к собственному API и добавляет таблицу ссылок.
Тестовые данные Firebase не переносятся. Существующие аккаунты и задачи PostgreSQL сохраняются.
Публикация 1С и её база не меняются. Файлы database.json остаются на сервере,
пароль повторно вводить не нужно.

## 1. Резервная копия и файлы

1. В pgAdmin: база **mobile_tasks** → правая кнопка → Backup/Резервная копия.
   Выберите формат Custom и сохраните файл в папку резервных копий на сервере.
   Проверьте, что операция завершилась успешно.
2. Скопируйте прежнюю папку `D:\WebApps\MobileTasksApi` в резервную папку.
3. В IIS остановите только пул **MobileTasksApi**.
4. Замените файлы в `D:\WebApps\MobileTasksApi` всем содержимым папки
   `publish` нового архива. Не создавайте вложенную папку publish.
5. **Не удаляйте и не заменяйте**
   `D:\WebApps\MobileTasksConfig\database.json`. Там прежние настройки.

## 2. Создание таблиц

На сервере откройте PowerShell от имени администратора:

```powershell
& 'D:\WebApps\MobileTasksApi\MobileTasks.Api.exe' --migrate
```

Ожидаемый результат:

```text
Migration completed. Schema version: 4
```

Команда использует сохранённые настройки PostgreSQL. Она создаёт схему
`mobile_tasks` в базе **mobile_tasks** и таблицы:

- `users` — учётные записи приложения с хешами паролей;
- `sessions` — хеши токенов сессий и сроки действия;
- `tasks` — задачи, авторы, исполнители, статусы и даты;
- `task_events` — создание, взятие, завершение и комментарии;
- `schema_migrations` — журнал применённых миграций;
- `task_links` — ссылки на материалы, WhatsApp и Telegram (миграция 2).

Повторный запуск команды допустим: существующие записи не удаляются.
Миграция выполняется в транзакции; одновременно запущенные миграции
сериализуются блокировкой PostgreSQL. При ошибке изменения откатываются.
Команда откажется работать, если в настройках имя базы отличается от
`mobile_tasks`, или версия схемы новее API. Автоматической миграции
при запуске сайта нет.

Если команда выводит `Migration failed`, оставьте пул остановленным и
пришлите строку с кодом ошибки, без файла с паролем.
`42501` обычно означает отсутствие прав создавать схему/таблицы:
проверьте владельца базы mobile_tasks — mobile_tasks_api.

## 3. Проверка сайта

Запустите пул **MobileTasksApi**. В браузере НА СЕРВЕРЕ откройте:

```text
http://127.0.0.1:8088/health/schema
```

Ожидаемый ответ (HTTP 200):

```json
{"status":"ok","schemaVersion":4,"requiredVersion":4}
```

`/health/database` по-прежнему должен вернуть `database: connected`.
Без миграции API возвращает 503 `schema_not_ready`, а `/health/schema`
показывает `migration_required`.

Порт/пул/права папки остаются прежними. Общий перезапуск IIS не требуется.
Обновляйте только собственный сайт MobileTasksApi.

## Проверка приложения

1. На телефоне через мобильный интернет откройте https://alf-mobile-tasks.duckdns.org/health/live.
2. Установите APK 2.2.0. Зарегистрируйте новый аккаунт: имя, email, пароль от 12 символов.
3. Откройте «Общие задачи», создайте тестовую задачу и добавьте ссылку/контакт.
4. На втором телефоне зарегистрируйте другого пользователя. Он должен увидеть задачу, взять её и завершить. На первом телефоне исполнитель и статус обновятся в течение 15 секунд, пока приложение открыто.
5. Отключите интернет и проверьте просмотр сохранённых задач. Изменения требуют сети.

Если из офиса домен не открывается, а через мобильный интернет работает, настройте локальный DNS: `alf-mobile-tasks.duckdns.org` → `10.10.10.254`. URL в приложении остаётся HTTPS с доменным именем, иначе сертификат не совпадёт. Сертификат и привязки IIS менять не нужно.

Архив содержит `publish/` — эти файлы идут в папку сайта. Документацию `.md` храните отдельно от сайта. `Configure-Database.ps1` при уже работающей базе повторно запускать не нужно. Прежний файл `D:\WebApps\MobileTasksConfig\database.json` сохраняется.

Миграция 3 добавляет таблицу task_files с бинарным содержимым вложений. Старые задачи и ссылки сохраняются. Максимум одного файла — 10 МБ; IIS по умолчанию допускает такой размер. Если на сайте ранее установили собственное ограничение размера запроса, задайте минимум 10485760 байт. Файлы входят в резервную копию PostgreSQL.

Миграция 4 добавляет состояния/события действий, devices и push_queue. Для включения уведомлений дополнительно выполните PUSH_SETUP.md; ключ Firebase в архив не входит.
