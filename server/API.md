# MobileTasks.Api — контракт v1

Серверная часть ASP.NET Core 10 + Npgsql. Все пути ниже относительны к
адресу сайта. Сейчас проверяем локально на http://127.0.0.1:8088.

## Авторизация

`POST /api/auth/register`:

```json
{"email":"developer@example.com","name":"Программист","password":"YOUR_PASSWORD_12_OR_MORE_CHARACTERS"}
```

Email нормализуется (trim + lowercase), уникален без учёта регистра;
имя 1–80 символов, пароль 12–256. Ответ 201:

```json
{"token":"OPAQUE_BEARER_TOKEN","expiresAt":"2026-12-17T10:00:00+00:00","user":{"id":"UUID","email":"developer@example.com","name":"Программист"}}
```

`POST /api/auth/login`: email/password → такой же ответ, HTTP 200.
`GET /api/auth/me`: текущий профиль.
`POST /api/auth/logout`: аннулировать текущий токен, HTTP 204.

Кроме register/login, все `/api`-методы требуют заголовок:

```text
Authorization: Bearer OPAQUE_BEARER_TOKEN
```

Сессии действуют 30 дней; сохраняется только SHA-256 от случайного
256-битного токена. Пароли обрабатывает ASP.NET Core Identity PasswordHasher
(PBKDF2, 210000 итераций). Изменение настроек API/перезапуск IIS не сбрасывает
сессии. Пять неправильных паролей блокируют вход в учётную запись на 15 минут;
неправильный пароль/неизвестный аккаунт/блокировка возвращают общий HTTP 401.
Сброс пароля и подтверждение email пока не реализованы.

Вход/регистрация: до 30 запросов в минуту с одного IP, все API-запросы:
до 300 запросов в минуту с IP. Превышение: 429 и Retry-After: 60.
Максимальный размер тела запроса: 64 KiB. Ответы не кэшируются браузером.
Токены/пароли нельзя передавать в URL или сохранять в журналах.

## Задачи

Все зарегистрированные пользователи видят все общие задачи.

| Метод | Путь | Результат |
|---|---|---|
| GET | /api/tasks | Страница задач |
| POST | /api/tasks | Создание задачи |
| GET | /api/tasks/{id} | Карточка задачи |
| POST | /api/tasks/{id}/claim | Взять задачу |
| POST | /api/tasks/{id}/complete | Завершить свою задачу |
| GET | /api/tasks/{id}/events | Страница истории/комментариев |
| POST | /api/tasks/{id}/comments | Добавить комментарий |

Создание:

```json
{"id":"CLIENT_GENERATED_UUID","title":"Название задачи","description":"Описание"}
```

Название 3–160, описание до 10000 символов. Поле id можно опустить, но для
повтора после потери ответа клиент должен заранее сохранить UUID и послать
тот же id и те же данные. Первый ответ 201, повтор той же операции 200.
Другой автор/другое содержимое при том же id → 409. Автор, статус и
исполнитель устанавливаются сервером, не из полей запроса.

Карточка: id/title/description/status/authorId/authorName/assigneeId/
assigneeName/createdAt/updatedAt/completedAt. UUID — строки, даты — ISO 8601
UTC; отсутствующий исполнитель/дата завершения — null.

Список: `?status=new|active|done&mine=true&limit=50&cursor=...`.
mine означает «я исполнитель». Для собственных выполненных задач:
`?status=done&mine=true`. Размер страницы 1–100, по умолчанию 50.
Ответ: `{"items":[...],"nextCursor":"..."}`. nextCursor=null в конце.
Порядок: дата создания DESC, UUID DESC; фильтры при продолжении сохранять.
Курсор непрозрачный, передавать через URL-encoding.

Взятие: атомарный переход new → active с назначением текущего пользователя.
Из двух разных одновременных претендентов один получит 200, второй 409.
Повтор победителя возвращает 200 без второго события. В историю claimed
записывается email (логин) исполнителя. Завершение: active → done,
только своим исполнителем; повтор завершения тоже 200 без дублирования.
Переоткрытие, переназначение, редактирование и удаление пока не реализованы.

Комментарий:

```json
{"id":"CLIENT_GENERATED_UUID","comment":"Текст комментария"}
```

Текст 1–4000. Повтор с тем же UUID, автором, задачей и текстом идемпотентен.
История: items с id/taskId/actorId/actorName/kind/comment/createdAt,
nextCursor; limit/cursor работают как в списке задач, порядок DESC.

## Ошибки и диагностика

Доменные ошибки: `{"code":"...","message":"..."}`. Неверные типы JSON и
некорректные параметры также могут вернуть стандартный пустой HTTP 400.
400 — неверные данные; 401 — требуется вход; 404 — задача не найдена;
409 — конфликт состояния/UUID; 429 — лимит; 503 — база или схема не готовы.
Клиент должен обрабатывать HTTP-код даже без JSON-тела. После сетевого сбоя
проверять текущее состояние; не создавать новую задачу с новым UUID вслепую.

`GET /health/live`: запущен процесс; `GET /health/database`: соединение с БД;
`GET /health/schema`: версия схемы. Последние два доступны только локально
на сервере; forwarded-заголовки не используются для обхода проверки адреса.

## Разработка и тесты

Код разделён на Auth (пароли/сессии), Tasks (задачи/история), Data
(соединение/миграции/диагностика), Api (маршруты/ошибки).
Интеграционный runner в tests предназначен ТОЛЬКО для отдельного PostgreSQL
localhost:15439 с тестовой ролью mobile_tasks_api, не для рабочего сервера.
Он очищает схему mobile_tasks в изолированной базе mobile_tasks.

Android 2.1.0 использует это API. Оно не принимает реквизиты OData и не взаимодействует с 1С.

## Материалы и контакты (схема 2)

Все методы требуют Bearer-сеанс. Любой зарегистрированный пользователь видит материалы и может добавить свои. Автор берётся из сеанса, не из JSON.

- `GET /api/tasks/{id}/links` → `{ "items": [...] }`, порядок по дате и UUID.
- `POST /api/tasks/{id}/links` → `{ "status": "ok" }`. Тело: `{ "items": [{ "id": "UUID", "name": "Клиент", "url": "https://wa.me/996555123456", "kind": "whatsapp" }] }`.

Виды: `web`, `file`, `image`, `whatsapp`, `telegram`. От 1 до 20 ссылок в пакете, имя до 160 символов, URL до 4096, только HTTP(S) без userinfo; контакты требуют HTTPS и допустимый домен. Размер всего тела до 64 КиБ. Пакет атомарный. Повтор с теми же UUID и полями разрешён; конфликт UUID или автора даёт 409. Ответ списка включает `id`, `taskId`, `name`, `url`, `kind`, `authorId`, `authorName`, `createdAt`. Для бинарных файлов используются отдельные методы /files, описанные ниже.

## Файлы (схема 3)

Все методы требуют Bearer. GET /api/tasks/{taskId}/files возвращает items с id,name,size. PUT /api/tasks/{taskId}/files/{id}?name=URL_ENCODED_FILENAME принимает бинарное тело до 10485760 байт. ID — UUID клиента; повтор с теми же автором, задачей, именем и байтами допустим, конфликт — 409. Пустой файл и имя с разделителями пути/управляющими символами отклоняются. GET /api/tasks/{taskId}/files/{id} отдаёт оригинал как application/octet-stream с Content-Disposition attachment. Доступ имеют зарегистрированные пользователи приложения.
