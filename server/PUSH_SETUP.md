# FCM общих задач — версия 2.2.1

Задачи и файлы остаются в PostgreSQL. Firebase Cloud Messaging используется для доставки уведомлений. APK собран с существующим клиентским google-services.json проекта mobile-tasks-in-1c, пакет kg.devtasks.app.

## 1. Сервер API

Обновите сайт из publish нового ZIP и примените миграцию как в TASKS_SETUP.md. Требуемая схема — 4. При остановленном пуле:

```powershell
& 'D:\WebApps\MobileTasksApi\MobileTasks.Api.exe' --migrate
```

Существующие задачи, аккаунты и файлы сохраняются. Миграция добавляет устройства и очередь push, а также состояния и события отказа/передачи/отмены.

## 2. Ключ Firebase

1. В Firebase Console откройте проект **mobile-tasks-in-1c → Настройки проекта → Сервисные аккаунты / Service accounts → Firebase Admin SDK → Generate new private key**.
2. Сохраните полученный служебный JSON **только на Windows Server**, как `D:\WebApps\MobileTasksConfig\firebase-service-account.json`. Это отдельный приватный ключ сервера; клиентский google-services.json его не заменяет.
3. Убедитесь, что для проекта включён **Firebase Cloud Messaging API (HTTP v1)**. Служебная учётная запись должна иметь право отправки сообщений (Firebase Cloud Messaging API Admin).
4. Скопируйте Configure-Push.ps1 в D:\WebApps\Setup, запустите PowerShell от администратора:

```powershell
& 'D:\WebApps\Setup\Configure-Push.ps1'
```

Скрипт дополняет существующий database.json разделом Push и устанавливает права чтения для пула. Пароль PostgreSQL сохраняется.

5. Перезапустите только пул MobileTasksApi. На сервере проверьте `/health/schema` (версия 4) и `http://127.0.0.1:8088/health/push`. Ожидается configured=true. Это проверка наличия конфигурации, а не подтверждение успешной доставки Google.
6. Серверу нужен исходящий HTTPS к oauth2.googleapis.com и fcm.googleapis.com. Оставьте службу сайта запущенной. Очередь хранится в БД, ошибки отправки повторяются раз в 5 минут до 12 попыток, события старше суток удаляются.

## 3. Телефоны

Установите APK 2.2.1, войдите в серверный аккаунт и разрешите уведомления Android. Полученный FCM-токен регистрируется на API для текущего пользователя. Для общих задач автору уведомление о собственной новой задаче не отправляется. Сообщения содержат только вид события; названия/описания задач и пароли в FCM не передаются.

При выходе приложение перестаёт показывать push для этого аккаунта. Токены устройств имеют срок регистрации 30 дней и обновляются при входе/новом токене. При запрете уведомлений, отсутствии Google Play Services, сети или принудительной остановке приложения Android доставка может задержаться или потребовать повторного запуска приложения.

Для сборки APK на другом компьютере нужен app/google-services.json того же проекта. Для GitHub Actions добавьте секрет FIREBASE_ANDROID_CONFIG с содержимым клиентского файла. Приватный служебный ключ в репозиторий и приложение не помещается.

## 4. Проверка доставки

На втором телефоне войдите другим аккаунтом. Создайте общую задачу на первом: уведомление должно прийти на второй. По нажатию откроется раздел общих задач.

Локальные тесты проверяют запись очереди, права и регистрацию устройств. Реальная доставка Google FCM проверяется после подключения служебного ключа и разрешения уведомлений на телефоне.

Официальная документация: [серверный HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api), [приём сообщений Android](https://firebase.google.com/docs/cloud-messaging/android/receive-messages).

Уведомления из 1С отключены. Обработчик /api/integrations/1c/new-task удалён, приложение игнорирует старые сообщения с kind=odata. Если подписки на события в 1С уже создавались, отключите их, чтобы 1С не обращалась к удалённому обработчику. Для обновления достаточно схемы 4; повторно создавать базу не требуется.
