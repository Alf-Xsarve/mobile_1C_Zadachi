# FCM и уведомления из 1С — версия 2.2.0

Задачи и файлы остаются в PostgreSQL. Firebase Cloud Messaging используется для доставки уведомлений. APK собран с существующим клиентским google-services.json проекта mobile-tasks-in-1c, пакет kg.devtasks.app.

## 1. Сервер API

Обновите сайт из publish нового ZIP и примените миграцию как в TASKS_SETUP.md. Требуемая схема — 4. При остановленном пуле:

```powershell
& 'D:\WebApps\MobileTasksApi\MobileTasks.Api.exe' --migrate
```

Существующие задачи, аккаунты и файлы сохраняются. Миграция добавляет устройства и очередь push, а также состояния и события отказа/передачи/отмены.

## 2. Ключ Firebase

1. В Firebase Console откройте проект **mobile-tasks-in-1c → Настройки проекта → Сервисные аккаунты / Service accounts → Firebase Admin SDK → Generate new private key**.
2. Сохраните полученный служебный JSON **только на Windows Server**, как `D:\WebApps\MobileTasksConfig\firebase-service-account.json`. Это отдельный приватный ключ сервера; клиентский google-services.json его не заменяет.
3. Убедитесь, что для проекта включён **Firebase Cloud Messaging API (HTTP v1)**. Служебная учётная запись должна иметь право отправки сообщений (Firebase Cloud Messaging API Admin).
4. Скопируйте Configure-Push.ps1 в D:\WebApps\Setup, запустите PowerShell от администратора:

```powershell
& 'D:\WebApps\Setup\Configure-Push.ps1'
```

Скрипт дополняет существующий database.json разделом Push и устанавливает права чтения для пула. Пароль PostgreSQL сохраняется. Генерируется отдельный ключ интеграции 1С в one-c-webhook-key.txt; повторный запуск использует прежний ключ.

5. Перезапустите только пул MobileTasksApi. На сервере проверьте `/health/schema` (версия 4) и `http://127.0.0.1:8088/health/push`. Ожидаются configured=true и oneCConfigured=true. Это проверка наличия конфигурации, а не подтверждение успешной доставки Google.
6. Серверу нужен исходящий HTTPS к oauth2.googleapis.com и fcm.googleapis.com. Оставьте службу сайта запущенной. Очередь хранится в БД, ошибки отправки повторяются раз в 5 минут до 12 попыток, события старше суток удаляются.

## 3. Телефоны

Установите APK 2.2.0, войдите в серверный аккаунт и разрешите уведомления Android. Полученный FCM-токен регистрируется на API для текущего пользователя. Для общих задач автору уведомление о собственной новой задаче не отправляется. Сообщения содержат только вид события; названия/описания задач и пароли в FCM не передаются.

При выходе приложение перестаёт показывать push для этого аккаунта. Токены устройств имеют срок регистрации 30 дней и обновляются при входе/новом токене. При запрете уведомлений, отсутствии Google Play Services, сети или принудительной остановке приложения Android доставка может задержаться или потребовать повторного запуска приложения.

Для сборки APK на другом компьютере нужен app/google-services.json того же проекта. Для GitHub Actions добавьте секрет FIREBASE_ANDROID_CONFIG с содержимым клиентского файла. Приватный служебный ключ в репозиторий и приложение не помещается.

## 4. Новые задачи 1С

Для мгновенного уведомления сама 1С должна отправить событие создания задачи на API. Одного чтения OData телефоном для этого недостаточно.

В `one-c/МобильныеУведомления.bsl` подготовлен серверный общий модуль и примеры подписок. В конфигураторе создайте серверный неглобальный общий модуль **МобильныеУведомления**, разрешите вызов серверных процедур и вставьте код. Укажите внешний URL OData, в точности совпадающий с адресом подключения в телефоне, и ключ из one-c-webhook-key.txt. Не помещайте заполненный секретом модуль в публичный GitHub.

Для объекта **Задача.ТехЗаданияДляПрограммистов** создайте две подписки: ПередЗаписью и ПриЗаписи. Сигнатуры обработчиков сгенерируйте в конфигураторе для вашей версии платформы; используйте тела процедур из примера. После первой записи новая задача запускает фоновую отправку события, при изменении существующей отправка не выполняется. Требуются поддержка фоновых заданий и права их запуска. Ошибки фоновых заданий проверяйте в журнале 1С; автоматическое восстановление неотправленных событий при недоступности API потребует постоянной очереди в вашей конфигурации.

Контракт: POST https://alf-mobile-tasks.duckdns.org/api/integrations/1c/new-task, заголовок X-OneC-Key, JSON `{"taskId":"GUID задачи","source":"внешний корень OData"}`. Повтор одного GUID в одной базе безопасен: сервер убирает дубликаты. Телефон показывает уведомление только если такой адрес базы подключён у текущего локального профиля и включён. Различающиеся внутренний/внешний адреса считаются разными источниками — используйте единый домен.

## 5. Проверка доставки

На втором телефоне войдите другим аккаунтом. Создайте общую задачу на первом: уведомление должно прийти на второй. Создайте задачу в 1С: после успешного фонового задания уведомление должно прийти на телефоны с этим подключением. По нажатию откроется приложение; список 1С при необходимости обновите в соответствующем разделе.

Локальные тесты проверяют запись очереди, права и регистрацию устройств. Реальная отправка в Google и событие вашей конфигурации 1С проверяются после подключения ключа и подписок.

Официальная документация: [серверный HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api), [приём сообщений Android](https://firebase.google.com/docs/cloud-messaging/android/receive-messages).
