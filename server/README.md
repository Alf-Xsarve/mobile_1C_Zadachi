# Сервер задач в IIS

ASP.NET Core 10 API с PostgreSQL: регистрация, вход и сессии, задачи,
назначение исполнителя, завершение, комментарии, история и постраничные списки.
Android 2.0.0 использует этот API по HTTPS. Схема PostgreSQL: версия 2.
Материалы задач сохраняются как внешние ссылки; файлы не загружаются на сервер.

**Обновление установленного API и создание таблиц:** [TASKS_SETUP.md](TASKS_SETUP.md).
**Контракт методов:** [API.md](API.md).
Первое подключение PostgreSQL: [DATABASE_SETUP.md](DATABASE_SETUP.md).

## Подготовлено на сервере

- IIS и AspNetCoreModuleV2 из .NET 10 Hosting Bundle.
- Отдельный пул `MobileTasksApi`: No Managed Code, Integrated,
  Enable 32-Bit Applications=False, Identity=ApplicationPoolIdentity.
- Папка `D:\WebApps\MobileTasksApi`.

## Публикация для локальной проверки

1. Распакуйте содержимое `publish` из архива непосредственно в
   `D:\WebApps\MobileTasksApi`. В этой папке должны лежать `web.config`,
   `MobileTasks.Api.dll`, `MobileTasks.Api.deps.json` и
   `MobileTasks.Api.runtimeconfig.json`, а не ещё одна папка `publish`.
2. Дайте `IIS AppPool\MobileTasksApi` права чтения и выполнения для этой
   папки. В свойствах папки: Безопасность → Изменить → Добавить →
   Размещение: локальный сервер → имя указанной учётной записи →
   Проверить имена → Чтение и выполнение. Изменение и полный доступ
   этой сборке не требуются.
3. IIS → Сайты → Добавить веб-сайт:

   | Поле | Значение |
   |---|---|
   | Имя сайта | MobileTasksApi |
   | Пул | MobileTasksApi |
   | Физический путь | D:\WebApps\MobileTasksApi |
   | Тип | http |
   | IP-адрес | 127.0.0.1 |
   | Порт | 8088 (если свободен) |
   | Имя узла | пусто |

   Эта привязка доступна только на сервере. Она не изменяет сайты 1С и не
   требует открытия порта в брандмауэре. Если 8088 уже занят другим сайтом,
   выберите свободный порт и используйте его в адресах ниже.
4. На НОВОМ сайте откройте Проверка подлинности → Анонимная проверка
   подлинности → Изменить → Удостоверение пула приложений. Анонимная
   проверка должна быть включена для этой проверки запуска.
   Настройки существующих сайтов не меняйте.
5. Откройте в браузере НА СЕРВЕРЕ:
   `http://127.0.0.1:8088/health/live`.
   Должен вернуться HTTP 200 и JSON со `status: "ok"`,
   `service: "MobileTasks.Api"`, `stage: "tasks-api"`.
6. Откройте `http://127.0.0.1:8088/`. Ответ объясняет, что это проверка
   запуска. Для проверки базы отдельно откройте `/health/database` после
   выполнения DATABASE_SETUP.md.

Не меняйте привязки существующего сайта с OData. Для этой проверки не нужен
общий перезапуск IIS: запускайте только новый сайт/пул.
Пароли и данные подключения в эту сборку не входят.

## Если сайт не запустился

- 500.19: проверьте наличие AspNetCoreModuleV2 и опубликованного web.config.
- 500.31: проверьте наличие .NET 10 и ASP.NET Core 10 Runtime из Hosting Bundle.
- 500.30: смотрите Просмотр событий → Журналы Windows → Приложение
  (источники IIS AspNetCore Module V2 и .NET Runtime).
- 401.3: проверьте права чтения/выполнения для учётной записи пула.

Пришлите текст ошибки без паролей и секретов. Не включайте подробные ошибки
для публичного доступа.

## Сборка на компьютере разработчика

Требуется .NET 10 SDK:

```powershell
dotnet publish .\server\MobileTasks.Api\MobileTasks.Api.csproj -c Release -o .\server\publish
```

SDK Web генерирует `web.config` при публикации. На сервере достаточно
соответствующего Hosting Bundle, SDK там не требуется.
