# Задачи / Dev — Android, Kotlin

Отдельное приложение для программистов: общие задачи на собственном сервере PostgreSQL, задачи из нескольких баз 1С, личная история работы и оформление с жёлтыми акцентами. Android 8.0+; версия 2.0.0.

Android подключается к **https://alf-mobile-tasks.duckdns.org** через HTTPS.
Сервер: [ASP.NET Core + PostgreSQL](server/README.md).
Установка с нуля: [IIS и HTTPS](server/IIS_SETUP.md), [подготовка PostgreSQL](server/DATABASE_SETUP.md).
Перед установкой APK 2.0.0 обновите IIS и схему базы до **2** по
[инструкции обновления](server/TASKS_SETUP.md). [Контракт API](server/API.md).
Данные и аккаунты Firebase не переносятся: зарегистрируйте новый серверный аккаунт.

## Возможности

- Общие аккаунты на собственном API: email, пароль от 12 символов, имя и сохранение сеанса между запусками. Сеанс действует 30 дней, затем нужен повторный вход. Восстановление пароля по почте пока не реализовано. Прежние локальные профили 1С доступны отдельной кнопкой.
- Раздел «Общие задачи»: создание задач в PostgreSQL, автор и исполнитель, статусы «Свободно → В процессе → Выполнено», фильтры и поиск, обновление раз в 15 секунд, когда приложение открыто.
- Материалы общих задач: ссылки на внешние файлы, изображения и страницы. Можно добавить их в черновик или в существующую задачу; другие пользователи увидят материалы автоматически. Адреса в описании задачи открываются по нажатию.
- Контакты клиента: WhatsApp и Telegram по международному номеру, username Telegram или готовой ссылке; открытие чата по нажатию.
- Взятие общей задачи выполняется транзакцией: у задачи один исполнитель. Завершить задачу может только её исполнитель; это проверяется также сервером и атомарным UPDATE PostgreSQL.
- Несколько подключений OData, каждое со своим пользователем и паролем 1С. Задачи разных баз с одинаковым GUID не смешиваются.
- Добавление базы по QR-коду с автоматической проверкой и сохранением подключения. Сканер доступен из главного экрана, списка подключений и формы новой базы.
- Компактная шапка и карточки: больше задач на экране. Строки списка переиспользуются при прокрутке; полное описание доступно в деталях.
- Общий список, «Мои», «Готово», поиск по загруженным данным, фильтры по статусу и базе, загрузка следующих страниц.
- Просмотр описания, комментария и исполнителя, взятие задачи в работу и изменение статуса.
- Сохранение задач на телефоне, чтение без сети, обновление личных задач, включая задачи за пределами первой страницы.
- Проверка версии перед записью и условный PATCH с If-Match. При конфликте приложение предлагает обновлённые данные, сохраняя чужие изменения.
- При неопределённом результате запроса приложение сохраняет ожидающее действие и проверяет его чтением. Автоматической повторной записи нет.
- Три оформления, светлая/тёмная/системная тема, размер текста, анимации, подтверждение действий и настройки кеша.

## Первый запуск

1. Установите APK и зарегистрируйтесь по email. Для старого профиля выберите «Войти в локальный профиль».
2. Откройте «Настройки → Мои базы 1С → Добавить базу».
3. Укажите название, корневой URL вида `https://server.example/base/odata/standard.odata/`, логин и пароль пользователя 1С.
4. Приложение проверит `$metadata`, перечисление статусов и загрузит первые 50 задач. Для остальных нажмите загрузку следующей страницы.

С телефона `localhost` указывает на сам телефон. Для базы в офисе нужен доступный адрес сервера; для Android Emulator адрес компьютера обычно `10.0.2.2`. Для локальных публикаций поддерживается HTTP; для внешнего подключения используйте HTTPS.

Новые аккаунты и общие задачи хранятся на собственном сервере. Все зарегистрированные пользователи видят общие задачи и исполнителей. Задачи из 1С показываются отдельно, подключения и пароли 1С остаются на телефоне.

Прежние локальные профили 1С доступны через «Войти в локальный профиль». Подключения разделены по профилям: автоматического переноса из профиля Firebase или между телефонами нет. Старые локальные данные не удаляются.

`google-services.json` больше не нужен. Папка `firebase/` и `FIREBASE_SETUP.md` оставлены как архив прежней реализации и при сборке 2.0.0 не используются.

### Подключение по QR-коду

Поместите в QR-код JSON, заменив пример адресом и реквизитами своей базы:

```json
{
  "type": "devtasks_1c_connection",
  "version": 1,
  "name": "База разработчиков",
  "odataUrl": "https://server.example/base/odata/standard.odata/",
  "username": "Пользователь1С",
  "password": "Пароль1С"
}
```

Название `name` необязательно: приложение получит его из пути базы. Поддерживаются QR-коды приложения бухгалтерии с `type: accounting_1c_connection` и теми же полями. Профиль приложения при этом не меняется: QR содержит только подключение к 1С.

Нажмите значок QR в шапке списка задач или «Сканировать QR-код» в подключениях, разрешите камеру и наведите её на код. Повторно нажимать «Подключить» не требуется. Дубликат адреса не создаётся. Если база недоступна или данных недостаточно, приложение покажет ошибку и оставит форму для исправления. При отказе в доступе к камере доступны ручной ввод и переход в настройки разрешений.

## Настройка 1С

Опубликуйте стандартный интерфейс OData и предоставьте пользователю права чтения задач, метаданных и записи реквизитов задачи. Проверяется EntitySet `Task_ТехЗаданияДляПрограммистов` с полями:

| Назначение | Поле |
| --- | --- |
| Ключ / версия | `Ref_Key`, `DataVersion` |
| Название / номер / дата | `Description`, `Number`, `Date` |
| Описание | `Описание` |
| Статус | `Статус` |
| Исполнитель | `Программист` |
| Комментарий | `Комментарий` |
| Пометка удаления | `DeletionMark` |

Статусы читаются из `EnumType` с именем `СтадияДоработокПрограммистовV2` в `$metadata` каждой базы. Подтверждённые значения:

| Отображение | Значение для записи |
| --- | --- |
| Свободно | `Свободно` |
| В процессе | `ВПроцессе` |
| Выполнено | `Выполнено` |
| Отменено | `Отменено` |

При взятии задачи один PATCH записывает статус, логин профиля в `Программист` и новую строку истории в `Комментарий`. Предыдущий комментарий сохраняется. При других переходах также добавляется строка с логином и временем. Поля `Executed` и `ДатаВыполненияДоработки` автоматически не изменяются: смена бизнес-статуса не запускает завершение задачи платформы.

Смена статуса требует сети. Офлайн можно читать сохранённые данные; очередь автоматических изменений не отправляется. Недоступность одной базы не мешает обновлять остальные. Проверку реального сервера следует начать на тестовой задаче: нужны фактические права записи, поддержка DataVersion/If-Match и обработчики вашей конфигурации.

## Хранение

Локальные профили разделены по владельцу. Пароль локального профиля хранится как PBKDF2-HMAC-SHA256 с солью и 600 000 итераций. Серверный пароль на телефоне не хранится: API проверяет его хеш, выдаёт отзывной bearer-токен и хранит только SHA-256 этого токена. Токен, кеш общих задач и материалы шифруются AES-GCM в каталоге `noBackupFilesDir`, ключ хранится в Android Keystore. Подключения, пароли 1С, кеш 1С и настройки также зашифрованы. Резервное копирование приложения отключено.

Без сети доступны сохранённые списки. Создание, взятие и завершение общих задач требуют связи с сервером. Повторная отправка создания задачи или пакета ссылок использует прежние UUID и не создаёт дубликаты. Обычный выход удаляет токен с телефона и пытается отозвать его на сервере; без сети удаление локальное, серверный сеанс истекает сам через 30 дней.

## Сборка

Откройте корень проекта в Android Studio. Требуются JDK 17+, Android SDK 36 и Build Tools 36.0.0. Gradle Wrapper 9.6.0 и Android Gradle Plugin 9.1.0 закреплены в проекте; Kotlin предоставляется AGP.

Создайте собственный `local.properties` (не коммитится):

```properties
sdk.dir=D\:/Development/Android/Sdk
```

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
# При подключённом устройстве или запущенном эмуляторе:
.\gradlew.bat connectedDebugAndroidTest
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Это отладочная сборка; для публикации настройте собственную release-подпись. GitHub Actions собирает APK и сохраняет его в артефакте `devtasks-android-debug`.
